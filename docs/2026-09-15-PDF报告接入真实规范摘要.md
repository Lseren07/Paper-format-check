# PDF 报告接入真实规范摘要（rules.source）

日期：2026-09-15

## 目标

把检测报告里那句占位文案（「当前报告依据项目实际加载的规则文件生成。」）换成**可追溯的真实规范依据**：报告要能说明依据哪份规范原件的哪一条，以及每条错误分别违反了哪一条。

## 数据链路

```
附件1：电子科技大学成都学院毕业论文（设计）撰写格式规范.docx
        ↓ 条款化提炼（含 4 张排版表：文首 / 正文 / 文尾 / 纸张规格）
rules/default.json 的 source 块
        ↓ 契约 RuleSet.source（RuleSource / RuleClause）
backend/app/services/rule_summary.py
        ↓                                  ↘
services/report.py（PDF「检测依据」章节）   api/report.py 响应 data.rule_source
```

## 规范来源的具体内容

`source.clauses` 共 11 条，每条都标注出处章节（如「三、论文排版（一）正文部分」）：

| 条款 | 出处 | 校验方式 |
| --- | --- | --- |
| 论文结构与装订顺序 | 一、毕业论文（设计）结构 | 自动（1 项） |
| 封面、摘要与关键词 | 三、论文排版（一）文首部分 | 自动（22 项） |
| 目录 | 三、论文排版（一）文首部分 | 自动（10 项） |
| 正文主体与章节标题 | 三、论文排版（一）正文部分 | 自动（32 项） |
| 参考文献与文尾部分 | 三、论文排版（一）文尾部分 | 自动（22 项） |
| 图、表与公式 | 三、论文排版（三）图表和公式 | 自动（3 项） |
| 页眉与页码 | 三、论文排版（二）页眉和页码 | 自动（1 项） |
| 页面设置与打印规格 | 四、论文打印规格 | 自动（1 项） |
| 参考文献著录格式 | 三、论文排版（四）参考文献 | 人工核对 |
| 量与单位 | 三、论文排版（五）量和单位 | 人工核对 |
| 正文章节内容组织 | 二、正文主体说明 | 人工核对 |

另附 3 条人工核对提示（字数、查重率 25%、封面与教务表格/装订顺序）。92 项启用规则全部有归属，无悬空、无重复引用。

## 关键决策

1. **不做「假依据」**：规则集没有 `source` 时，摘要返回 `available: false`，报告直说「未登记来源规范，请联系管理员补充」，而不是编一句看起来合理的话。
2. **条款按 rule id 精确归属，而非按检测器类型**：早期版本按 `check_types` 汇总，导致「参考文献」条款显示「自动（73 项）」这种失真数字（把全库 font 规则都算进去了）。改为每条条款声明自己的 `rules` 列表后，计数准确（22/32/3…），并能把错误直接回指到条款。
3. **测试不解析 PDF**：把版面组装抽成 `build_report_story`，测试直接断言 Flowable 内容，避免为测试引入 PDF 解析依赖。
4. **旧规则文件兼容**：`electronic-tech-cdu-v1.json` 的字符串 `source` 仍可加载，只是没有条款明细。

## 验证

- 后端全量 `pytest backend` → **97 passed**（原 85 + 新增 12）。
- 样例论文（`uploads/T42754861376d.docx`，检出 107 个问题）生成报告：3 页，条款表、错误溯源、人工核对提示均已渲染；示例见 `docs/示例报告_含真实规范依据.pdf`。

## 后续可做

- 前端「检查规范」页可直接消费 `rule_source`（当前只有 `report/create` 返回，若前端要独立展示，可补 `GET /api/v1/rules/source`）。
- `source` 可再补 `version` / `effective_date` 字段：附件1 未标注发布文号与生效日期，暂不猜测填写。
- 新增检查项时，若未归入任何条款，`unmapped_rule_ids()` 会暴露出来，建议在新增规则的流程里固定跑一次这条断言。
